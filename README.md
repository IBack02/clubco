# NIS CLUBS — локальная база данных

Приложение обрабатывает запросы через API Next.js и сохраняет данные в SQLite на этом компьютере. Отдельный сервер БД устанавливать не нужно.

## Запуск

Из корня проекта:

```bash
npm install
npm run dev
```

Откройте http://localhost:3000. Перед запуском автоматически создаётся `.env`, проверяется клиент Prisma и применяются миграции. Клиент генерируется только при отсутствии, изменении схемы или версии Prisma. Существующие данные сохраняются.

Если зависимости уже установлены, достаточно `npm run dev`. Для подготовки базы без запуска сайта:

```bash
npm run db:setup
```

## Где хранятся данные

По умолчанию файл SQLite находится в `prisma/dev.db`. Путь задаётся в `.env`:

```dotenv
DATABASE_URL="file:./dev.db"
```

Относительный путь считается от каталога `prisma`. Можно указать абсолютный путь, например `file:C:/data/nis-clubs.db`; каталог должен существовать и быть доступным для записи. Все пользователи сайта обращаются к одной базе на компьютере, где запущен Next.js.

`AUTH_SECRET` в `.env` создаётся автоматически при первом запуске. Сохраните этот файл, чтобы сессии продолжали работать после перезапуска. `.env` и локальные файлы БД исключены из Git.

Для просмотра таблиц и записей:

```bash
npm run db:studio
```

Если вы изменили схему Prisma или обновили пакет Prisma, перед `npm run db:setup` остановите Next.js и Prisma Studio этого проекта. На Windows они могут удерживать DLL движка: её замена приведёт к `EPERM`. Обычный повторный запуск с неизменённой схемой DLL не заменяет.

Для резервной копии остановите приложение и скопируйте `prisma/dev.db` в безопасное место. Обычный запуск и повторное применение миграций не очищают базу.

## Что сохраняется

- Регистрация и изменения профиля — в `users`; пароли хранятся в виде хешей.
- Заявки на создание клубов, их статусы и комментарии администратора — в `club_requests`.
- Вступления — в `join_requests`, членство — в `club_members`. Как и раньше, вступление происходит сразу; запись запроса получает статус `approved`. Если поля не переданы, имя и контакты берутся из профиля.
- Клубы, владельцы, расписания, анонсы и достижения — в соответствующих таблицах.
- Комментарии и лайки к анонсам — в `comments` и `announcement_likes`.

Заявки на создание доступны в профиле пользователя и панели администратора. Вступление и одобрение заявки сохраняют все связанные изменения одной транзакцией; повторное вступление и повторное рассмотрение не создают дубликатов.

## Основные API

Все адреса относительные, на том же локальном сервере. Для записи нужна авторизация через cookie после входа.

| Метод | Адрес | Действие |
|---|---|---|
| POST | `/api/auth/register` | Зарегистрировать пользователя |
| POST | `/api/auth/login` | Войти |
| GET / PATCH | `/api/auth/me` | Прочитать / изменить профиль |
| GET / POST | `/api/requests` | Получить / отправить заявку на клуб |
| POST | `/api/requests/:id/approve` | Одобрить заявку и создать клуб (администратор) |
| POST | `/api/requests/:id/reject` | Отклонить заявку (администратор) |
| POST | `/api/clubs/:id/join` | Вступить и сохранить запрос |
| GET | `/api/join-requests` | Прочитать вступления: свои, в свои клубы, либо все для администратора |
| POST | `/api/announcements/:id/comments` | Сохранить комментарий: `{ "content": "Текст" }` |
| PUT / DELETE | `/api/announcements/:id/like` | Поставить / убрать лайк |

## Демонстрационные данные

При необходимости, после `npm run db:setup`:

```bash
npm run db:seed
```

Seed заполняет только пустую БД и выполняется одной транзакцией. Если база уже содержит данные, он пропускается: пользовательские записи не изменяются и демонстрационные записи не дублируются.

## Проверка и сборка

```bash
npm run typecheck
npm run test:integration
```

Интеграционная проверка собирает проект, создаёт отдельную временную SQLite БД и проверяет HTTP-запросы, права доступа, повторные запросы и сохранение после перезапуска сервера. Рабочая БД не используется тестами.

Для запуска собранного приложения:

```bash
npm run build
npm start
```

Для размещения приложения с этой конфигурацией нужен сервер с постоянным диском, доступным для записи. SQLite-файл не подходит для хранения данных в эфемерной файловой системе Vercel Functions.
